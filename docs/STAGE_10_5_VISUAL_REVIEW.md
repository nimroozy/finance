- **Themes:** light + dark for launcher, customer list, and payment workflow;
  light for the remaining reviewed screens
- **Total screenshots:** 60

## Known environment note

This sandbox lacks the PHP `bcmath` extension (install blocked by
organization egress policy). Endpoints that decorate invoice balances
(`Money::normalize`/`bcadd`) return 500 here, so the customer-detail
Overview tab and the payment invoice step render their honest error/empty
state instead of populated financial data. This is an environment gap, not
a UI defect — see `docs/STAGE_10_5_KNOWN_ISSUES.md`. On a runtime with
`bcmath` these screens show fully populated data.
