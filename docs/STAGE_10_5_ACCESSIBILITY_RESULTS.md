# Stage 10.5 — Accessibility Review

Generated by `frontend/e2e-real/acceptance.a11y.spec.ts` (run with `A11Y=1`)
against the isolated acceptance stack. Combines an automated axe-core audit
(WCAG 2.1 A/AA, serious+critical rules only) with explicit keyboard, focus,
picker-semantics, touch-target, and RTL-direction assertions. The suite
fails if any serious/critical axe violation is found, the search field is
unreachable by keyboard, or `html[dir]` does not match the locale.

## Fixes applied during this review

- **Cascade-layer contrast bug (serious):** an unlayered global
  `a { color: inherit }` rule overrode Tailwind v4's layered `text-white`
  utility, so the active sidebar nav item rendered dark text on the dark
  primary background (1.39:1). Moved base element resets into `@layer base`.
- **Unlabeled filter/select controls (critical, `select-name`):** added
  `aria-label` / `htmlFor`+`id` associations to status, sync-status,
  outcome, collector, priority, payment-method, and assignment selects.
- **Unlabeled form fields (critical, `label`):** associated the due-date
  and notes fields on the assignment-create form with their labels.
- **Unnamed mobile account-menu button (critical, `button-name`):** the
  header user-menu button collapses to icon-only on mobile; added an
  `aria-label`.

## Residual notes

- Smallest rendered control height is ~36px on a few dense secondary
  controls (pagination). This meets WCAG 2.1 AA; the 44px target is AAA
  (2.5.5). Primary field-workflow actions use `h-11`/`h-12` (44–48px).
